# Project review, 2026-11-09 (code and process audit)
**Version**: 1.0.0 · **Author**: Caio Camargo + Claude (Fable 5.2, review session) · **Created**: 2026-11-09 · **Updated**: 2026-11-09
**Status**: open. Tasks R1–R24 below are in QUEUE *Proposed* for the orchestrator to rank.
**Purpose**: An independent review asked for by Caio (2026-11-09): what in the build needs improving. Unlike
[`REVIEW-2026-10-11.md`](REVIEW-2026-10-11.md) (milestones, pillars, docs), this one audits the **code and the tests**:
four read-only audits (physics sim, app and renderer, economy and saves, the test suite) plus a pass over process and
repo state, at `main` = `6bdf2ed` (v1.288). **Confirmed** = reproduced by running code headless; **read** = from reading
only. Nothing was run on the GPU, so on-screen effects are inferred.

---

## 1. The short version

- **The core is sound.** `kepler()` survived 200,000 fuzzed cases (e 0–50, both directions) with exact energy; one
  orbit in `physStep` drifts under 0.05 m against Kepler; rails agree across step sizes; no per-frame GPU leaks; the
  full suite is 844 / 0 with no flakes in two runs.
- **The defects are at the seams between sessions' work**: a reset list that missed fields another session added, a
  cache key a later feature invalidated, a test that proves only its author's change. Three shared guards are missing:
  static checking, a state schema, isolated tests.
- **Green tests mean less than the logs say**: 6 of 10 arithmetic mutations in sim code passed everything run against
  them, and the app layer (960 KB) is never executed by a test.
- **The process costs more than it returns**: the two files every session reads at start are ~410 KB, the human queue
  doesn't drain, and finished work sits unmerged on branches.
